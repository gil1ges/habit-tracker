# Трекер привычек

Django-приложение для ведения личных привычек: пользователь регистрируется, создаёт привычки, отмечает выполнения и смотрит статистику по прогрессу на аналитической панели.

## Возможности

- регистрация, вход, выход, смена и восстановление пароля;
- профиль пользователя с email, телефоном, аватаром и описанием;
- CRUD для привычек с периодичностью, целью, цветом и статусом активности;
- отметка выполнения привычки за текущий день с заметкой;
- аналитика по привычкам: сводные показатели, таблица, графики Matplotlib и JSON-статистика;
- файловая отправка писем для восстановления пароля;
- логирование действий приложения в консоль и файлы в `logs/`.

## Стек

- Python 3;
- Django;
- SQLite;
- Bootstrap 5 через CDN;
- Matplotlib для графиков;
- Requests для внешней цитаты с русским fallback;
- Pytest и pytest-django для тестов;
- Pillow для работы с изображениями профиля.

## Структура проекта

- `config/` — настройки Django, корневые URL, ASGI/WSGI;
- `core/` — главная страница и общие template tags;
- `users/` — кастомная модель пользователя, регистрация, admin-настройки и сигналы авторизации;
- `habits/` — модели привычек и выполнений, формы, валидаторы, CRUD-представления;
- `analytics/` — расчёт статистики, графики, цитата и API статистики;
- `templates/` — HTML-шаблоны интерфейса;
- `tests/` — pytest-тесты для пользователей, привычек, аналитики и regex-утилит;
- `sent_emails/` — письма восстановления пароля при локальном запуске;
- `static/` и `media/` — статические файлы и пользовательские загрузки.

## Запуск проекта

1. Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Для Windows:

```bash
py -m venv .venv
.venv\Scripts\activate
```

Для fish shell:

```fish
source .venv/bin/activate.fish
```

2. Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

3. Примените миграции:

```bash
python manage.py migrate
```

4. При необходимости создайте администратора:

```bash
python manage.py createsuperuser
```

5. Запустите сервер разработки:

```bash
python manage.py runserver
```

После запуска приложение будет доступно по адресу `http://127.0.0.1:8000/`.

## Основные адреса

- `/` — главная страница;
- `/auth/register/` — регистрация;
- `/auth/login/` — вход;
- `/habits/` — список привычек;
- `/analytics/` — панель аналитики;
- `/analytics/api/stats/` — JSON-статистика;
- `/admin/` — административная панель Django.

Письма восстановления пароля сохраняются в каталог `sent_emails/`, потому что в настройках используется файловый email backend.

## Тесты

Запуск всего набора тестов:

```bash
pytest
```

Тесты проверяют регистрацию и вход, CRUD привычек, отметки выполнений, доступ к аналитике, JSON API и набор regex-валидаторов.

## Условное распределение работы на 4 участников

Для командного отчёта проект можно представить как работу четырёх участников:

1. Участник 1 — пользователи и авторизация: кастомная модель `CustomUser`, форма регистрации, шаблоны входа, выхода, смены и восстановления пароля, интеграция с Django auth.
2. Участник 2 — привычки: модели `Habit` и `HabitCompletion`, валидаторы, формы, CRUD-представления, страницы списка, создания, редактирования, просмотра и удаления привычек.
3. Участник 3 — аналитика: сервисы подсчёта статистики, графики Matplotlib, аналитический dashboard, JSON API и получение мотивирующей цитаты.
4. Участник 4 — инфраструктура, интерфейс и качество: настройки проекта, маршрутизация, Bootstrap-шаблоны, русификация интерфейса, логирование, pytest-конфигурация и тестовое покрытие.
